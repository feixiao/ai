## 第 1 章 AI Agent 入门

### 核心公式与框架

- **Agent = LLM + 上下文 + 工具**（大脑 + 眼睛 + 手脚）
- **ReAct 循环**：思考 → 行动 → 观察，周而复始推进任务
- **Harness 工程**：模型之外的运行与治理层——提供上下文、工具接口、约束、验证与纠正

### 工程演进弧线

```
提示工程 ⊂ 上下文工程 ⊂ Harness 工程 ⊂ Loop 工程 ⊂ Graph 工程
```

### 三层护栏（按绕过难度递增）

| 层级 | 防护内容 |
|:---|:---|
| **上下文层** | 输入拦截 / 提示注入检测 |
| **执行层** | 工具风险评级 / 人工介入 |
| **数据层** | 数据库行级权限 / 底层校验 |

### 关键设计模式

- 提议者-审核者（自审不可靠，必须引入外部验证）
- 渐进式披露（按需加载能力，而非一次性全部展示）
- 只增不改（KV Cache 友好）
- 边界集 + 保留集（验证改进同时防止退化）
- 最小 diff 与可回滚

### 实践要点

1. **优先扩展接口**：底层模型固定时，扩展上下文与工具比等更强模型见效更快
2. **编排从简到繁**：单次提示 → 确定性工作流 → 自主 Agent，避免预设冗余多 Agent 流水线
3. **ACI 防呆设计**：专用工具管高风险操作（含故障安全默认值），通用沙箱用于自由探索

## 第 2 章 上下文工程 ⭐ 最关键

### 上下文构成公式

$$\text{Context} = \underbrace{\text{System Prompt} + \text{Tool Schemas}}_{\text{静态前缀（KV Cache 强保障）}} + \underbrace{\text{Trajectory}}_{\text{动态增长轨迹}} + \underbrace{[\text{Agent Status}]}_{\text{末尾状态栏}}$$

### 核心概念

| 概念 | 要点 |
|:---|:---|
| **API 结构** | 四种消息角色：`system`、`user`、`assistant`、`tool`；模型 API 无状态，每次需完整重构消息历史 |
| **KV Cache & Prompt Cache** | 利用前缀不变性复用历史计算；任何前缀变动（哪怕一个空格）都会导致缓存失效 |
| **Agent Skills** | 领域能力模块化与渐进式披露；元数据目录常驻，核心正文按需加载 |
| **Agent 状态栏** | 在上下文末尾追加动态元信息（TODO 列表、工具调用计数等），将隐式状态显式化 |
| **上下文压缩** | 解决"装得下但找不准"的注意力稀释问题；分层手段：截断、直删、摘要、窗口化、子 Agent 隔离 |

### 核心洞察

> **上下文窗口是一台"只有一半的检索引擎"**——擅长精准检索，却缺乏自动归纳层。注入预计算好的结构化知识，远优于迫使模型在数万 token 原始历史中扫描。

> **缓存即架构约束**：Prompt Cache 带来近 10x 成本与延迟红利，倒逼架构遵循"前缀只增不改、动态信息永远追加末尾、隔离优于事后压缩"。

### 实践要点

1. **固化静态前缀**：系统提示词和工具定义切忌动态排序；动态信息统一追加到轨迹末端
2. **严守标准 API 格式**：避免自行拼接纯文本流（如 `USER:` / `ASSISTANT:`）
3. **流程驱动（SOP）优于规则堆砌**：按操作流程分步引导并明确边界与反例
4. **状态栏化解循环死锁**：由 Harness 代码维护 `<agent_status>` 追加注入末尾
5. **子 Agent 物理隔离**：海量中间噪声的任务委托独立子 Agent，仅回传提炼结论

## 第 3 章 用户记忆和知识库

### 记忆体系

| 维度 | 内容 |
|:---|:---|
| **评估三层次** | 基础回忆 → 多会话检索 → 主动服务 |
| **认知科学映射** | 情景记忆（事件）、语义记忆（知识）、程序记忆（流程） |
| **四种存储格式** | Simple Notes → Enhanced Notes → JSON Cards → Advanced JSON Cards |
| **进阶形态** | User as Code：类型化可执行代码（聚合、冲突检测交由确定性函数） |

### 混合检索流水线

```
稠密向量（语义泛化）+ 稀疏检索 BM25（精确匹配）
        ↓ RRF 倒数排名融合
    Cross-Encoder 重排序
```

### 结构化索引

| 方案 | 特点 |
|:---|:---|
| **RAPTOR** | 自底向上树状摘要，擅长由宏入微 |
| **GraphRAG** | 实体关系网络，擅长多跳与消歧 |
| **文件系统范式** | L0/L1/L2 目录分层按需渐进加载 |

### 智能体化 RAG（Agentic RAG）

将检索从"单向管道"升级为 ReAct 主导的动态工具调用——Agent 自主决定何时检索、检索什么。

### 核心洞察

- **知识变更 = 提议者 + 审核者的 PR 闭环**：禁止模型直接覆盖主库
- **仅追加优于即时覆写**：追加日志 + 检索时排序 + 后台定期去重重组（"睡眠学习"）
- **原始案例平铺 ≠ 知识可用**：必须在索引阶段离线抽象出统计摘要与规则边界

### 实践要点

1. **检索层强制权限过滤**：多租户权限在检索阶段完成，绝不能依赖 LLM 自行保密
2. **切块补全上下文**：采用 Contextual Retrieval 注入背景说明
3. **检索结果防注入**：外部数据打来源标签，与系统指令严格隔离

## 第 4 章 工具

### 工具设计哲学

- **ACI（Agent-Computer Interface）**：以 Agent 目标而非底层 API 为中心
- **通用优先**：代码解释器等通用元能力通常优于过度细分的专用工具
- **形态与披露解耦**：能力形态（专用/Skill）决定单项 token 成本；披露策略（全量/按需/主动发现）决定同时展现的数量

### 工具分类与设计

| 工具类型 | 关键设计 |
|:---|:---|
| **感知工具** | 只读，支持缓存与高并发；结构化候选、分页游标、显式截断 |
| **执行工具** | 输入校验 → 沙箱隔离 → 幂等重试 → 独立模型审批 → 执行-验证-反馈闭环 |
| **协作工具** | `spawn`/`cancel`/`send_message`/`list` 管理子 Agent 生命周期 |

### 工具生态

- **MCP 协议**：标准化专用工具通信
- **Skill Hub**：分发文档化能力
- **主动发现**：两层语义匹配 + Tool Search 避免全量 schema 挤爆上下文

### 核心原则

- **参数传递保真性**：模型感知的世界与工具执行的世界必须绝对一致
- **异构双审**：高危不可逆操作需不同模型家族互审（Proposer-Reviewer）
- **Sidecar 隐形门控**：主模型流式输出时并行触发轻量模型进行安全分类

### 实践要点

1. **描述重于模型**：工具描述写清"何时用"与"做不到什么"，参数给具体字面量示例
2. **长输出防爆**：超限时保留首尾 50 行 + 明确标注省略行数 + 全量落盘引导按需读取

## 第 5 章 Coding Agent 与通用 Agent

### 核心论断

> **开放型通用 Agent = Coding Agent + 文件系统**

Coding Agent 的优势不在模型单体多强，而在软件工程现成设施（测试、类型检查、CI、版本控制）天然提供了高可验证性 Harness。

### 基础工具箱（7 个核心工具）

Code Interpreter、Bash Shell、读文件、写文件、编辑文件、Glob、Grep + 文件系统（Markdown 记忆、SOUL.md、CLAUDE.md 等项目指令文件）

### 代码作为元能力（六大维度）

| 维度 | 示例 |
|:---|:---|
| 思维工具 | 符号计算、约束求解 |
| 业务规则硬约束 | 能用代码强制的规则绝不依赖提示词 |
| 多媒体生成 | Slidev / Blender API |
| 系统适配器 | 日志解析、RPA |
| 生成式 UI | A2UI 协议、Artifact 模式 |
| Agent 自举 | 自我修复与自我复制 |

### 故障恢复四层

API 故障 → 工具故障 → 上下文故障 → 控制流故障，结合分级恢复与熔断机制。

### 实践要点

1. 读文件强制标注行号；长命令输出截断并存盘
2. 文件编辑优先用字符串首尾匹配或唯一子串替换，降低行号漂移
3. 提议者-审核者解耦：代码生成（Proposer）与视觉审查（Reviewer）独立拆分
4. 权限下沉至数据层：动态生成代码的权限控制必须在数据层（如数据库行级安全策略）

## 第 6 章 交互：观察与动作空间的扩展

### 四大交互场景

| 场景 | 核心挑战 |
|:---|:---|
| **异步事件驱动** | 外部输入统一为结构化事件流，支持跨回合执行 |
| **语音全双工** | 级联 → 端到端全模态 → 全双工三代范式演进 |
| **Computer Use (GUI)** | SoM / DOM 定位 + 动作后必须重新观察确认状态 |
| **机器人物理控制** | VLA 动作分块（Action Chunking）隐藏推理延迟 |

### 统一系统原语

$$\text{交互原语} = \{\text{唤醒}, \text{安全点}, \text{取消}, \text{抢占}, \text{快慢分离}\}$$

### 快慢路径分离（双脑架构）

解耦前台毫秒级低延迟交互与后台高延迟深度规划。

### 实践要点

1. **安全点与取消**：异步多事件时在每轮交互边界显式定义安全点，配置级联取消与熔断
2. **隔离环境**：长期自主 Agent 部署虚拟机/手机隔离文件系统
3. **闭环状态验证**：GUI 点击或机械臂抓取后严禁假设成功，必须重新读取反馈

## 第 7 章 Agent 的评估

### 评估环境五要素

数据集（用例与任务）→ 环境状态（可重置）→ 工具接口（原子操作）→ 评分标准（Rubric）→ 交互协议（轮数上限与终止信号）

### 两个核心指标

$$\text{Pass@}k = 1 - (1-p)^k \quad \text{（能力上限：多次尝试只要成功一次）}$$

$$\text{Pass}^k = p^k \quad \text{（业务可靠性：连续 k 次都不能出错）}$$

当 $p = 0.6$ 时：$\text{Pass@}5 \approx 99\%$，但 $\text{Pass}^5 \approx 7.8\%$。**高风险场景必须盯紧 $\text{Pass}^k$。**

### 评估集三大来源

1. **公开基准**：横向对照与粗筛
2. **自建业务集**：贴合真实业务分布
3. **生产轨迹回流**：线上问题案例抽取

### 两层回归任务

- **端到端回归**：检验全链路能力是否退化
- **轨迹前缀回归**：冻结首错前上下文，针对性验证特定决策边界

### 自动化评估

- **LLM-as-a-Judge**：异构模型交叉评判，交换候选展示顺序消除位置偏差
- **失败归因**：必须定位导致偏离的**首个错误**（而非后续连锁反应）

### 内部评估基础设施

消融实验 → A/B 测试 → 双层特性开关 → 提示词敏感性测试（纳入 CI） → 隐私感知分析

### 实践要点

1. **Rubric 设一票否决项**：幻觉造假、未授权破坏性操作直接判 0 分
2. **区分机制指标与目标指标**：切勿将直接调整的机制误当优化目标
3. **统计显著性**：配对分析（McNemar / 配对 Bootstrap）+ 多随机种子验证

## 第 8 章 模型后训练

### 四阶段演进

```
预训练（通识基础）→ Mid-training（领域知识+长上下文）→ SFT（固化格式与协议）→ RL（强化决策策略）
```

### 核心论断

> **SFT 记忆，RL 泛化；数据与环境比算法更重要。**

- SFT：换了数据 + Loss Masking 的下一词预测，倾向拟合示范
- RL：最大化期望奖励以寻优，实现泛化

### 关键技术

| 技术 | 要点 |
|:---|:---|
| **RLVR** | 基于确定性验证器校验最终状态 |
| **RLVP** | "奖励结果、惩罚路径"：$R = \text{Normalize}(\text{Outcome}) + \beta \cdot \text{Normalize}(\Phi_{\text{path}})$ |
| **在轨蒸馏 (OPSD)** | 学生模型自主探索，教师模型在学生前缀上提供逐 token 概率监督 |

### 能力探测

$$\text{Pass@}k = 1 - (1-p)^k$$

若合理 $k$ 下仍接近 0 → RL 无法有效探索，需先补底座。

### 实践要点

1. **分级递进**：pass@k ≈ 0 或格式无法解析 → 先 Mid-training → SFT 稳定格式 → 再 RL
2. **严防 Reward Hacking**：验收验证运行在隔离环境，对模型不可见
3. **监控数值对齐**：Sampler 与 Trainer 概率比一致性 + 保留集防灾难性遗忘

## 第 9 章 Agent 的持续进化

### 双循环架构

```
在线循环：执行任务 → 追加不可变审计日志（只执行，不学习）
离线循环（睡眠学习）：聚类轨迹 → 消解冲突 → 生成最小更新提案 → 跑通回归
```

### 三层验证器

| 层级 | 验证内容 |
|:---|:---|
| **结果验证** | 代码/环境真实状态 |
| **过程验证** | 业务规则/权限/操作序列 |
| **质量验证** | LLM-as-a-Judge + Rubric 量表 |

### 四种更新载体

1. **经验知识库**：事实与例外
2. **Prompt 与 Skill**：策略与判断原则
3. **程序与 Harness**：确定性工作流与硬约束
4. **模型参数**：高维感知与内化风格

### 核心洞察

- **保存经历 ≠ 从经历中学习**：堆积日志只是检索素材，真正的学习源于多轨迹对照与独立验证
- **双集验证**：更新提案必须同时通过边界集（验证改进）与保留集（防退化）
- **可信根隔离**：Agent 可提议修改规则，但**决无权修改验证器、评测用例与发布门禁**

### 实践要点

1. **确定性约束优先入代码**：能用程序拦截的高风险操作切忌堆在 Prompt 中
2. **最小 Diff + 保留出处**：自动优化 Prompt 时生成局部补丁并附轨迹溯源
3. **证据与指令物理隔离**：外部获取的内容仅视为数据，严防提示注入污染经验库
4. **定期修剪**：周期性归档过期知识、合并重复规则，防止长期上下文腐化

## 第 10 章 多 Agent 协作

### 架构双维度

| 维度 | 选项 |
|:---|:---|
| **上下文** | 共享全量轨迹 vs 隔离上下文（进程级协作） |
| **拓扑** | 对等协作 / 管理者编排 (Orchestration) / 去中心化编舞 (Choreography) |

### 多 Agent 增益判据

> 多 Agent 优于单 Agent 的关键是**协作是否引入了新信息**（如代码执行反馈、视觉渲染、工具检索）。缺乏外部反馈的纯文本自我辩论往往无增益。

### 进程通信三大机制

1. **工具调用参数**（同步）
2. **共享文件系统**（工作区、共享区、外部挂载、系统内置虚拟文件系统）
3. **消息总线**（异步 Pub/Sub）

### 系统不变量

> *"模型可以提出完成，但不能批准自己的完成。"*
> 系统的瓶颈在验证器，而非模型本身。

### 架构对应律（多 Agent = 操作系统）

| Agent 概念 | OS 对应 |
|:---|:---|
| LLM | CPU |
| 轨迹 | 进程内存 |
| 提示词 | 程序 |
| 文件路径 | 通用接口 |
| 子任务返回 | 结构化摘要 |

### 新型失败模式

- 文件并发与跨文件语义冲突
- 错误级联放大
- 同质趋同（共因失效）
- 相互推诿与循环失控
- 人类的"理解债与认知投降"

### A2A 协议

面向跨组织 Agent 互操作：能力声明（Agent Card）+ 任务状态机 + 不透明协作（仅交换产物与任务）。

### 实践要点

1. **资源倾斜**：最强推理模型分配给 Planner/Manager，子任务按复杂度动态分配步骤预算
2. **轻量传递与隔离**：Agent 间传递文件路径引用（Ref）而非全量内容；并发写入用乐观锁或独立 Git 分支
3. **级联优雅终止**：类似 Go `context`，清理孤儿进程；每个子 Agent 设独立 API Key、步骤上限与超时熔断
4. **警惕认知投降**：保持对核心交付物的人工理解与架构审查
