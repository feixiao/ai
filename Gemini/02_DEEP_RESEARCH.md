# 02. Deep Research 深度研究实战指南

Gemini 深度研究（Deep Research）不仅是普通联网搜索的简单摘要，而是一个具备自主规划能力的多智能体递归调研系统。它能够在十几分钟到数十分钟内，自动执行多轮深度网络爬取、多源信息交叉检验、反思补充并生成具备学术论文与专业券商研报品质的万字深度报告。

## 2. 投研深度实战：机构级行业竞争与个股尽调

在投资分析中，常规搜索往往只能得到泛泛的媒体通稿或二手新闻。通过精心设计的 Research Brief，可以让 Deep Research 像一名全职分析师一样完成高密度的尽职调查。

### 2.1 投资调研提示词架构（4 要素原则）
1. **背景与角色约束**：明确专业投资人视角，强调怀疑主义与法务会计视角。
2. **核心研究假设**：给出需要被证伪或证实的具体商业假设。
3. **数据维度清单**：强制要求必须覆盖的硬指标（如 TAM、客户留存率、单位经济模型、真实毛利）。
4. **反脆弱性质询（Red Teaming）**：强制要求搜寻空头观点、暴雷历史与竞争对手的尖锐评价。

### 2.2 实战模版：赛道与个股深度调研

```markdown
请针对【目标标的/细分行业，例如：高带宽内存 HBM 封装产业链】执行一份机构级深度研究报告。

报告必须覆盖以下深度模块，并强制标注原始事实来源链接：

1. 【行业真实供需与产能测算】：
   - 梳理目前全球前三大核心玩家的现有产能与未来 24 个月的扩产计划（单位：K 片/月）。
   - 交叉比对主要下游超大规模云厂商（CSP）采购订单的公开披露口径与第三方行业机构（如 TrendForce、Gartner）的预测差异。

2. 【核心技术路线竞争壁垒与良率】：
   - 对比不同技术路线（例如：MR-MUF 与 TC-NCF）在散热效率、翘曲控制、封装厚度方面的物理极限。
   - 调查各厂商关键制程的实际良品率瓶颈与专利诉讼卡点。

3. 【单体经济模型（Unit Economics）与议价权】：
   - 分析上游核心设备与材料（如专用临时键合胶、先进封装光刻设备）的供应链集中度。
   - 估算当前毛利率与净利率水平，推演未来产能过剩周期下的价格敏感性压力测试。

4. 【反向事实核查与空头论据】：
   - 重点检索行业资深从业者的匿名访谈纪要、专利无效宣告申请及潜在替代性颠覆技术。
   - 列出该投资论点（Investment Thesis）成立的前提条件中，最容易破裂的 3 个脆弱假设。
```

## 3. 全栈技术调研实战：前沿架构与选型可行性研究

在工程选型中，很多决策由于调研不充分而导致后期重构成本极高。Deep Research 可以全网挖掘 GitHub Issue、Post-Mortem 事故复盘、技术博客与基准评测。

### 3.1 技术调研典型场景
- **数据库与存储选型**：如在千万级写入场景下，ClickHouse、DuckDB、TimescaleDB 的实际资源开销与故障恢复成本横评。
- **全栈框架与部署模式**：Next.js App Router vs Remix/React Router v7 在微前端及边缘部署下的真实踩坑复盘。
- **大模型本地推理与微调框架**：vLLM、Ollama、TGI、SGLang 在特定高并发场景下的吞吐延迟对比。

### 3.2 实战模版：高并发架构选型调研

```markdown
请针对【特定技术选型，例如：千万级用户高频写入时序数据的实时分析存储架构】执行深度技术研究报告。

调研范围需深入到 GitHub 真实生产事故记录、核心开发者邮件列表及真实生产环境基准测试：

1. 【架构机制深度对比】：
   - 深入分析方案 A（如 ClickHouse）与方案 B（如 DuckDB + S3 Parquet）在内存管理、WAL 机制、合并树存储策略上的底层差异。
   - 绘制数据从客户端写入、内存 Buffer 聚合到底层磁盘落盘的完整路径。

2. 【真实生产事故与已知痛点分析（Post-Mortem）】：
   - 搜索并总结近两年公开的技术事故报告，列出该架构在高负载下最常发生的三种宕机或雪崩场景（如 OOM、Zookeeper 元数据瓶颈、合并积压）。
   - 列出社区内被广泛讨论但长期未彻底解决的 GitHub High Priority Issues。

3. 【运维复杂度与 TCO 综合测算】：
   - 评估集群运维门槛：是否需要专职 DBA？主从同步延迟如何恢复？扩容再平衡（Rebalance）耗时。
   - 测算在峰值 10 万 QPS 写入量下，典型的硬件配置（CPU 核心数、RAM、NVMe 规格）与云资源月度账单估算。

4. 【最终架构决策树与落地建议】：
   - 给出清晰的选型判定边界条件（如数据规模阈值、延迟要求阈值、团队人手匹配度）。
```

## 4. 深度研究结果的高效审校与防坑指南

Deep Research 生成的内容信息量极大，为了防止被错误数据误导，应建立标准化的审校流：

1. **信源逐级穿透**：
   - 重点检查报告中的核心数字（如市场规模、增长率、毛利率）。点击附带的原文链接，确认是否来自一手信源（如公司 10-K 表格、官方审计财报），排除营销自媒体互相引用的假数据。
2. **警惕幸存者偏差与时间差**：
   - 在研究前沿科技或高景气赛道时，检查搜索引用的数据年份，确保没有使用 1~2 年前已过时的产业预测。
3. **结合 NotebookLM 二次归档**：
   - 将 Deep Research 生成的万字 Markdown 报告连同其引用的关键 PDF/网页源文件，一键导入 NotebookLM，形成可随时点对点提问的交互式专题知识库。
