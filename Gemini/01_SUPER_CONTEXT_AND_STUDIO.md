# 01. 超大上下文与 Google AI Studio 实战指南

Gemini 3.1 Pro 及相关前沿旗舰模型原生支持 100 万至 200 万 Token 的上下文窗口。这一特性在实际工程和投研分析中带来了计算范式的质变：信息处理从传统的“向量切片检索（RAG）”转向“全量上下文原位推理（In-Context Full Attention）”。

---

## 1. 核心技术对比：超大上下文 vs 传统 RAG

传统的检索增强生成（RAG）在处理海量文档或大型代码库时存在固有的架构缺陷，而超大上下文窗口从底层机制上解决了这些问题：

| 评估维度 | 传统 RAG（切片 + 向量检索） | Gemini 100万+ 原生上下文 |
| :--- | :--- | :--- |
| **检索完整度** | 依赖 Top-K 向量相似度，容易丢失关键上下文片段 | 全量数据保留在上下文内，全局注意力直接捕捉 |
| **多跳推理能力** | 跨越多个段落或文件的因果链路极易在切片中被打断 | 原生支持跨几十万字线索的链式逻辑推导 |
| **全局统计与对比** | 无法准确执行全集统计（如“统计所有出现过的异常指标”） | 精准扫描全量数据，执行跨文档完整横向对比 |
| **工程维护成本** | 需搭建向量库、配置分块算法、调优 Embedding 与重排模型 | 仅需简单的数据文本拼接或文件上传，零向量运维成本 |

---

## 2. 全栈工程实践：整仓代码全景分析与重构

将整个中大型项目的代码打包送入 Gemini 3.1 Pro，可以实现跨越单个函数和模块的架构级理解。

### 2.1 适用工程场景
- **架构异味与循环依赖扫描**：找出跨目录模块间的隐式强耦合与死循环调用。
- **全局重构方案设计**：按照领域驱动设计（DDD）或分层规范，生成具体的迁移路径与重构计划。
- **端到端安全审计**：追踪从前端表单输入到后端路由、服务层、ORM 实体到数据库查询的完整数据流，检查 SQL 注入与未鉴权漏洞。
- **全链路 TypeScript 类型收敛**：分析所有 `any` 和隐式类型的传播链条，输出全局严苛类型系统定义。

### 2.2 上下文清洗原则
为了将有效 Token 最大化留给业务逻辑，在打包代码前应严格过滤下列干扰项：
1. 构建与依赖目录：`node_modules/`, `dist/`, `build/`, `.next/`, `venv/`, `target/`。
2. 版本控制与缓存：`.git/`, `.pytest_cache/`, `__pycache__/`, `.DS_Store`。
3. 二进制与静态富媒体：`.png`, `.jpg`, `.mp4`, `.wasm`, `.zip`。
4. 巨型锁文件：`package-lock.json`, `pnpm-lock.yaml`, `poetry.lock`（这些文件可能占用数万 Token 且对业务逻辑理解帮助极小）。

### 2.3 实战 Prompt 范式：整仓架构重构审计

```markdown
你是一名资深全栈架构师与代码重构专家。
以下附带的内容是本项目的全部核心源代码文件树与具体代码实现。

请执行全面的代码库全景审计，重点回答以下四个维度，并给出具体的代码示例：
1. 【模块耦合分析】：列出存在跨边界调用、循环依赖或职责过重的核心文件，绘制调用关系链。
2. 【TypeScript/类型安全收敛】：标出全局数据流中类型断言与隐式类型滥用的链路，给出严苛类型修复方案。
3. 【并发与异步缺陷】：排查前端与后端代码中可能导致竞态条件（Race Conditions）、死锁或未被捕获 Promise 的环节。
4. 【渐进式重构路线图】：按照低风险高收益原则，拆解为 3 个阶段的重构计划，列出每个阶段需修改的文件与接口向后兼容方案。
```

## 3. 个人投资实践：多份同行 10-K 与研报免切片深度横评

在个人投研中，最耗费精力的工作是对同赛道多家公司的年报（10-K / Annual Reports）以及财报电话会议（Earnings Call Transcript）进行横向交叉检验。Gemini 100 万 Token 允许直接将 3 至 5 家龙头公司整年的财报全部装载。

### 3.1 投资实战场景
- **真实财务质量对比**：穿透会计政策，对比研发费用资本化率、存货减值计提保守度、非经常性损益占比。
- **管理层表态一致性检验**：将连续 4 个季度的电话会议纪要同时输入，检查管理层对业绩指引（Guidance）的承诺与后续实际交付的差距。
- **产业链上下游交叉印证**：同时输入上游供应商、核心公司、下游客户的财报，验证订单真实性与库存去化周期。

### 3.2 实战 Prompt 范式：跨公司财务穿透横评

```markdown
你是一名严格遵循基本面投资与法务会计审视原则的资深证券分析师。
附件中包含了该行业 3 家核心公司（公司 A、公司 B、公司 C）最新财年的完整 10-K 年报及最近一期的电话会议纪要。

请对这 3 家公司的财务与经营质量进行深度横向对比，输出 Markdown 格式的专业报告：
1. 【自由现金流（FCF）真实性对比】：
   - 比较各家的“经营活动现金流净额 - 资本开支（CapEx）”。
   - 检查是否存在利用供应链金融拉长应付账款伪造经营现金流的迹象。
2. 【毛利率异动与定价权核验】：
   - 横向对比产品毛利率与销售费用率的变动趋势。
   - 分析哪家公司展现出了真正的产品定价权，哪家公司在通过降价和渠道压货维持收入规模。
3. 【电话会议关键矛盾穿透】：
   - 检索分析师提问环节中管理层回答含糊、闪烁其词的具体问题（列出原文引用）。
   - 对比管理层承诺的资本开支落地节奏与实际资产负债表新增固定资产、在建工程的数据匹配度。
4. 【财务红队压力测试】：列出每家公司潜在的 3 个最大财务脆弱点（如短期债务偿付压力、大客户集中度过高、商誉减值隐患）。
```

## 4. Google AI Studio 深度配置与最佳实践

Google AI Studio (`https://aistudio.google.com/`) 是直接释放 Gemini 模型原生能力的最强工具，其功能远比常规 Web 聊天界面更为专业严谨。

### 4.1 核心参数调优策略
- **Model 选择**：日常代码重构、研报精读首选 `Gemini 3.1 Pro` / `Gemini 2.5 Pro`；快速扫描与轻量提取首选 `Gemini Flash` 系列。
- **Temperature（温度）**：
  - 投研数据提取、代码重构、SQL/JSON 生成：设置为 **`0.0`**（确保确定性、计算准确性，彻底抑制随机幻觉）。
  - 架构方案设计、投资论文红队质询：设置为 **`0.2 ~ 0.4`**（兼具严谨逻辑与适度发散思维）。
- **Safety Settings（安全过滤阈值）**：
  - 在法律、财务审计及网络安全代码审查时，建议将过滤级别调至最低（Block None / Block Only High），防止模型对正常的财务异常审计或逆向工程代码产生误杀拦截。

### 4.2 结构化输出（Structured Outputs / JSON Schema）
在 AI Studio 中，启用 **`Structured Output`** 并输入 JSON Schema，可以强迫 Gemini 100% 按照预定字段返回合规的 JSON 数据，避免任何多余的客套废话或 Markdown 语法破坏程序解析：

```json
{
  "type": "object",
  "properties": {
    "company_name": { "type": "string" },
    "fiscal_year": { "type": "string" },
    "revenue_cagr_3yr": { "type": "number", "description": "3年营收复合增长率" },
    "free_cash_flow_quality_score": { "type": "integer", "description": "1-10分自由现金流质量评分" },
    "red_flags": {
      "type": "array",
      "items": { "type": "string" },
      "description": "审计发现的财务异常点清单"
    }
  },
  "required": ["company_name", "fiscal_year", "revenue_cagr_3yr", "free_cash_flow_quality_score", "red_flags"]
}
```

### 4.3 Context Caching（上下文缓存）
当喂入的代码工程或财报合集超过 **32,768 Tokens** 时，Google AI Studio 和 Gemini API 均支持 **Context Caching**：
1. **费用节省**：缓存的 Token 输入成本降低约 75% 以上。
2. **延迟降低**：后续轮次提问不再需要重复对 100 万 Token 进行全文前向计算，首字响应时间从十几秒骤降至数百毫秒。
3. **工作流模式**：将整个代码库或财报底表作为常驻缓存，连续针对不同问题（如“检查用户模块”，“分析折旧政策”）反复追问，体验极其流畅。
